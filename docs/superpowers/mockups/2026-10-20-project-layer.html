Ask the project3

the notebook's ask, scoped to this project's notes · prose on demand, nothing stored
What do we know about the interval at 25 °C?
Ask
partial
Two embryos imaged at 25 °C hatched about 18 % sooner than the 20 °C baseline. The baseline is well measured; the 25 °C side rests on one short run, so it is a lead, not a result.
  • Baseline twitching-to-hatching interval is 715 ± 22 min over three nights. n_1b77 n_2c03
  • At 25 °C, e1 and e2 hatched at 588 and 601 min. n_4f2a
  • The 25 °C run used 561 as well, which the baseline did not. n_9c01
Next: plan item 2.1 would give six embryos at 25 °C with the same channels as the baseline.
Sessions belong to the projectOne field on the session record, session.yaml.project_id, written by one filing door. The Sessions section is the file store filtered by it.
Context is a filter, not a folderNotes, observations, expectations and questions already hang off a session id. The project shows the global pools filtered by membership. Nothing moves on disk.
Synthesis is the ledger, then prose on demandNext = unblocked plan items. Predicted = expectations. Measured = outcomes and findings. Open = questions. All four exist today. A finding is a Note of kind finding, proposed by the agent, confirmed by a person. Ask renders prose from the notes when asked.
Linkages are one reference shape{source, key, title, url}, the shape plan items already carry, now also on the root campaign as strains and references. WormBase typed ids, CGC strains and WormAtlas pages all link.
Observability is an aggregationPer member session: holdings the Sessions tab computes, how the run ended from timelapse.yaml, errors and warnings from events.jsonl, turns and corrections from the interaction log. Live is the active session being a member.
Where plans live and how one startsPlan is a section of the project: the Plans tab canvas as it is today, with Doc, Graph, Board, Decide, Matrix and Timeline. Three ways to start: + New project with one line of description, + item by hand or from the Operate pane or a template, and Plan with Gently, which enters plan mode scoped to this project.
Everything edits through one doorEach entry edits in place and has add and remove. The agent uses the same store methods through its tools, so both announce and both land in the plan history. What the agent adds that would run hardware or claim a result arrives as suggested or proposed, never runnable until a person accepts.
One search, real sourcesThe add control is a typeahead over five sources queried in parallel: the lab's own names first and instantly, then genes from the Alliance API, strains from CGC, papers from Europe PMC, and WBls and WBbt terms from the EBI Ontology Lookup Service. Checked today: the Alliance, OLS, Europe PMC and Crossref answer JSON; CGC is HTML and parses; WormBase's own API refuses scripts, so WB ids arrive through the Alliance and OLS and the chip links to wormbase.org for a person. No model is involved: every line is a database record.

Project chip and filterEvery row shows its project from the session record, and a Project group joins the filter line with counts like the others. An unfiled session says so and offers to be filed.
One home, many itemsA session has one project, written on the session record by whoever files it: the agent when it runs a plan item, Start when the session already has one, the gate's picker, or this popover. A session that also served another project's plan item is linked to that item, which is what the inspector's link-session does today, and says so here.
The session-end noteOne deterministic observation from the holdings and notable events, no model call, so every night leaves a record in the project even when nobody asked.
Stages carry an ontology idA small dict in the organism plugin maps each stage to its WormBase life-stage term. The bar, the export and any note can show or link it.
